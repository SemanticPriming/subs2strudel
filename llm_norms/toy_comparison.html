Beyond Strudel: two LLM routes to concept‑feature norms

Strudel's pattern-grammar and a first pass at UDPipe dependency parsing both worked, but neither scaled cleanly to new languages or produced features that read like something a person would actually say. This is a small pilot testing two LLM-based replacements against real human norms — not a finished pipeline, just early signal to react to.

01

LLM as virtual participant

llama3.1 (open-weight, run locally via Ollama) is given the same instructions used to collect the human norms — the original Buchanan et al. (2019) task wording, duck / cucumber / stove examples included — and asked to list properties for one concept at a time. Each call uses a fresh sample (temperature 0.9, new seed), standing in for one "participant." Twenty such runs per concept are aggregated exactly like the human study: normalized_feature = participants producing X ÷ N × 100.

Prompt frame (condensed from materials/human/english_Buchanan2019.html) duck: is a bird, is an animal, waddles, flies, migrates, lays eggs, quacks, swims, has wings, has a beak, has webbed feet, has feathers, lives in ponds, lives in water, hunted by people, is edible … Now give the comma-separated list of properties for: {concept}
Caveat — phrases vs. words: the human norming pipeline atomizes each typed response down to individual content words before scoring, so a participant who wrote wags its tail shows up in the data only as the single feature tail (33% for dog) — not as a phrase, and not as wag either. The LLM elicitation here keeps phrases intact (wags_its_tail). The top-10 coverage numbers above use substring matching, which happens to catch cases like this one, but it's a loose fix: a properly fair comparison would explode LLM phrases into the same single-word units the human pipeline uses before scoring overlap, rather than leaning on substring luck.
02

LLM as corpus cleaner

The other route keeps the corpus grounding but drops Strudel's hand-built pattern-grammar. It reuses counts already sitting in archive/example/english_backward.csv — words dependency-parsed as modifying a concept noun in the existing subs2vec-derived corpus — and asks the same model to separate genuine semantic properties from parsing noise (fixed-phrase collocations, unrelated modifiers), then rescales by the surviving frequency mass.

What "dependency-parsed" means here

A dependency parser reads a sentence and labels which words grammatically attach to which other word, and how. In "a martial art class," it says martial is an amod (adjectival modifier) of art. Run over every sentence in the corpus that contains a concept, this gives a list of every word ever attached to that concept, tagged with the relation type, plus how often each attachment occurred — e.g. art ←amod— martial occurred 7,632 times. That count is what the "corpus freq" column below is built from. Strudel did the equivalent thing with its own hand-written pattern-grammar instead of a dependency parser (see the archived strudel_sups/strudel_report.pdf); this route substitutes a modern dependency parse for that grammar, then leans on the LLM to do the semantic filtering Strudel's stop-lists tried to do by hand.

Diagnosis: the backward-dependency extraction is dominated by amod relations — adjectives modifying the concept noun — so the candidate pool is mostly frequent collocations ("martial art", "big band") rather than the functional/associative properties people actually list ("painting", "instruments", "listening"). The LLM filter can discard obvious noise, but it can't manufacture properties that were never in the candidate pool to begin with. Fixing this needs richer relation types at extraction time (verb objects, prepositional attachments), not a better filter downstream.
03

For discussion

  • Does virtual-participant sampling feel legitimate as a stand-in for norm collection, or does it just reproduce the LLM's training-data priors dressed up as "probability"? What would we want to see before trusting it for a language with no existing human norms?
  • Is the corpus route worth saving by re-extracting with fuller dependency relations (verb-object, prepositional), or should OpenSubtitles text go straight to an LLM extractor instead of through a dependency parse first?
  • Where does reinforcement learning fit? The English human norms (data/human/) could serve as a reward/eval signal for tuning the elicitation prompt or scoring — worth investing in now, or only once one base approach is picked?
  • Which concepts should the next round cover — abstract vs. concrete, high vs. low frequency, or specifically words where the two methods disagree most?
