Beyond Strudel: two LLM routes to concept‑feature norms

Strudel's hand-built pattern-grammar worked, but doesn't scale cleanly to new languages, and an earlier pass at reusing pre-parsed dependency data turned out to be a dead end (see the aside in Section 02). This pilot tests two LLM-based replacements against real human norms — not a finished pipeline, just early signal to react to.

01

LLM as virtual participant

llama3.1 (open-weight, run locally via Ollama) is given the same instructions used to collect the human norms — the original Buchanan et al. (2019) task wording, duck / cucumber / stove examples included — and asked to list properties for one concept at a time. Each call uses a fresh sample (temperature 0.9, new seed), standing in for one "participant." Twenty such runs per concept are aggregated exactly like the human study: normalized_feature = participants producing X ÷ N × 100.

Prompt frame (condensed from materials/human/english_Buchanan2019.html) duck: is a bird, is an animal, waddles, flies, migrates, lays eggs, quacks, swims, has wings, has a beak, has webbed feet, has feathers, lives in ponds, lives in water, hunted by people, is edible … Now give the comma-separated list of properties for: {concept}
Caveat — phrases vs. words: the human norming pipeline atomizes each typed response down to individual content words before scoring, so a participant who wrote wags its tail shows up in the data only as the single feature tail (33% for dog) — not as a phrase, and not as wag either. The LLM elicitation here keeps phrases intact (wags_its_tail). The top-10 coverage numbers above use substring matching, which happens to catch cases like this one, but it's a loose fix: a properly fair comparison would explode LLM phrases into the same single-word units the human pipeline uses before scoring overlap, rather than leaning on substring luck.
02

LLM reading real corpus sentences

Strudel scans a window of tokens around each marked concept in the corpus and applies a hand-written pattern-grammar to decide whether a nearby word is a property, and how it's connected (see the archived strudel_sups/strudel_report.pdf, Section 3). This route does the same job — concept in, candidate property out — but asks llama3.1 to make that call directly from the raw sentence, in place of the regex-based connector-pattern grammar.

Corpus

A ~8MB byte-range slice (llm_norms/fetch_corpus_sample.sh) of the OPUS-OpenSubtitles v2024 English mono file — about 710K real subtitle lines out of the full ~9.5GB corpus. Kept at data/subs/, gitignored: it's a sample to prototype against, not ours to redistribute. For each concept, lines containing the word are found by simple matching, 25 are sampled, and each is sent to the model on its own with the sentence in context.

Sentence: {sentence} Does this sentence indicate a genuine property of {concept} — physical, functional, categorical, or behavioral? If yes, output ONE short property (e.g. "has_legs", "used_for_sitting"). If not: none

Worked example — six real extractions:

sentenceextracted property
“You said you'd even let the dogs come in.”can_be_pets
“You please sit on the chair.”used_for_sitting
“Now you rob me of the triumph of seeing you sent to the chair.”used_as_punishment
“Well, eat some green apples.”has_green_color
“J And the Adam's apple Is seven and a half”has_size
⚠ wrong sense — "Adam's apple" isn't the fruit
“But ambition, greed and lust for power destroy any hope for happiness.”elusive
Caveats from this run: (1) word sense — matching is on the surface string, so "Adam's apple" and "the Big Apple" get folded in with the fruit; Strudel's corpus sidesteps this by pre-marking which occurrences count as the target concept (NNCONCEPT tag) before extraction even starts. (2) a generic-guess bias — has_legs was the model's answer 19 times across all 100 sentences, including ones that never mention legs, suggesting it's a default fallback rather than a grounded read of the sentence. (3) small sample — 25 sentences per concept from one 8MB slice; several concepts got 0–5 "none" responses before there was enough text to work with.

superseded first attempt

Cleaning pre-parsed dependency data

Before pulling raw corpus text, the first attempt at a "corpus route" reused counts already sitting in archive/example/english_backward.csv — words dependency-parsed as modifying a concept noun in an earlier subs2vec pass — and asked the LLM to filter parsing noise (fixed-phrase collocations like martial art) from genuine properties. It didn't work: that extraction is dominated by amod (adjective-modifier) relations, so the candidate pool for a word like art was mostly frequent collocations, not the properties people actually list. An LLM filter can discard obvious noise but can't manufacture a property that was never in the candidate pool. Measured against the human norms for art / band / concert / radio, this route recovered 0% of the top‑10 human feature mass, across all four words — which is why the sentence-reading approach above exists.

03

For discussion

  • Does virtual-participant sampling feel legitimate as a stand-in for norm collection, or does it just reproduce the LLM's training-data priors dressed up as "probability"? What would we want to see before trusting it for a language with no existing human norms?
  • Does the corpus route need Strudel's concept-tagging step back — marking which occurrences of a word are really the target concept — before an LLM extractor can trust the sentences it's reading, given the Adam's-apple problem above?
  • How much does sample size matter here? 25 sentences from an 8MB slice already shows real signal for some concepts (chair: 57% coverage) and almost none for others (happiness: 0%) — is that a corpus-size problem or a concreteness problem?
  • Where does reinforcement learning fit? The English human norms (data/human/) could serve as a reward/eval signal for tuning either the elicitation prompt or the sentence-extraction prompt — worth investing in now, or only once one base approach is picked?
  • Which concepts should the next round cover — abstract vs. concrete, high vs. low frequency, or specifically words where the methods disagree most?
